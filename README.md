## Working With the Site

CompuToolsDist can act as a central page for release notes, build URLs, and basic links around the project.

A usual publishing cycle looks like this:

1. Edit the HTML so it reflects the current release.
2. Insert new build URLs or update the existing download links.
3. Deploy the resulting files to GitHub Pages or another static host.
4. Distribute the landing page address to users who need the release files.

When several builds are available, arrange the page so the intended download can be recognized quickly.

## Frequently Asked Questions

**How can I point the page to a different release?**  
Modify the relevant HTML and replace the existing download address with the URL for the new release.

**Is a build process required to view the repository?**  
No. The files form a static site that can be opened directly in a browser.

**Where do the release files belong?**  
Store them according to the directory layout expected by your static host, then reference them from the landing page.

**What can I inspect when the page fails to display properly?**  
Check the HTML paths, linked asset locations, and hosting settings before refreshing the deployed page.

**How are new revisions published?**  
Commit and publish the updated HTML, then revise the download references whenever the available build changes.
